# Editable delivery: distinguish the objects

Native architecture mode uses draw.io or PPT shapes, text and connectors. Reuse and restyle the bundled modules; compare rendered output with scientific material and reference. This gives object-level edits for the supported architecture primitives. SVG icons can remain scalable picture assets; they are not native point-editable PPT objects unless converted appropriately.

Raster-plus-text mode applies when the user explicitly asks to make text in an existing image editable. Inspect the accepted baseline; preserve the source PNG and all scientific meaning. Reconstruct only visible text using native text boxes and carefully matched cover regions or an explicitly authorized image-edit approach. Do not silently rewrite labels or claim the background illustration becomes editable. Dense texture, formulas or ambiguous text can prevent faithful conversion; disclose that boundary.

An editable-output request is sufficient authorization for the requested conversion; do not impose a second acceptance round when an existing approved image is already identified. A dissatisfied user asking for image revision needs that revision first. Respect an explicit review-before-conversion request.

Use actual installed font metrics and final-size text placement. Remove unintended PPT theme shadows. Check the exported PPT page in PowerPoint or another supported renderer, then inspect cover/text regions for old letters, clipping, color mismatch and changed arrows. XML validity alone is not visual acceptance. Do not represent a raster pasted into PPT as a native editable architecture.
