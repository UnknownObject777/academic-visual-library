# Draw from the uploaded style

Treat the actual reference as the design authority within explicit user constraints and scientific correctness. The agent can reason about the image directly; do not build a style ontology or generate a long style report first.

## Look for the visual identity

Observe the full reference, then establish color roles and visual language before choosing the target layout. Notice whether the reference uses a shared scene, small multiples, a central mechanism, spatial layering, a wide panorama or compact technical details. Also look at density/whitespace, illustration and mark language, strokes/arrowheads, shapes/surfaces, depth/texture, typography and semantic color relationships.

Choose the features that materially distinguish this reference and reproduce them coherently. A tiny internal note is sufficient. Do not always output this checklist or classify it into a fixed preset. A dark textured isometric style should not quietly become a white rounded-card diagram.

## Transfer the right things

For a new method transfer appearance and useful composition, while deriving modules, labels and connections from target content. A curved reference arrow can inform arrow treatment; its original feedback relationship cannot be imported unless supported. Reference-specific labels, results and scientific apparatus do not migrate automatically.

For exact redraw preserve source semantics. For a local edit preserve correct untouched regions and existing style. For several references, infer their roles from the request: e.g., one for composition, another for palette or illustration. Resolve material contradictions using explicit instructions and current context; ask only if the choice genuinely changes the intended result. Do not create an incoherent average of all references.

An empirical plot can borrow typography, colors, strokes, legend placement and panel spacing while keeping data, axes and comparison scales true. Decorative curves or fake measurements are never a style-transfer technique.

## Put the reference into production

Pass the actual inspected image through the selected renderer's supported reference input. Say which image supplies target content and which supplies style, and identify the necessary adaptation. If all required assets cannot be included using one supported reference mechanism, request reattachment rather than silently dropping a reference.

Vector/document drawing can use the reference as visual guidance without a raster generator. Build meaningful native objects and labels; preserve raster textures as assets if needed and disclose their editability. No promise of pixel-perfect reproduction across arbitrary styles and media. Do not change the requested renderer without a supported reason and a clear explanation.

## Compare the produced image

Compare side by side with the reference: does the composition/visual hierarchy, drawing language, material and text treatment still feel like the selected style? Check specific observable differences, not a generic “beautiful” or “academic” judgement. Then verify target scientific meaning and final-size legibility. Correct the most consequential mismatch without regenerating already-correct regions unnecessarily.
