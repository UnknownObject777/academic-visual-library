# Optional color examples

Uploaded references and the user's established paper colors come first. Observe actual fill/outline/text relationships and adapt them; no palette lookup, role-token schema or color report is required.

When no reference exists, a restrained starting point is dark text `#24323D`, neutral arrows `#334155`, and a few role-based accents. Examples:

| Treatment | Example accents |
|---|---|
| Categorical technical | `#0072B2`, `#E69F00`, `#009E73`, `#CC79A7` |
| Soft modular | pale blue `#EDF4FB` / dark blue `#194166`; pale green `#F3FBF0` / green `#3B7D23`; peach `#FBE3D6` / brown `#A94417` |
| Monochrome | `#212121`, `#616161`, `#9E9E9E` with distinct labels and line styles |

These examples do not restrict the style to flat, white or low saturation. Preserve intentional texture, gradients or dark surfaces from a supplied reference and test actual readability. Venue names, domains and module counts do not select a palette. Exact extracted hex values are estimates unless measured.

Use coherent roles across figures and check final-size readability. Color alone should not encode an important distinction when dual encoding is needed. A palette name does not certify contrast or accessibility; report measurements only when actually performed.
